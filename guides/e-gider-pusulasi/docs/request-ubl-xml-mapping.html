API

Request → UBL XML Mapping

Entegratörün gönderdiği JSON alanlarının UBL XML'deki karşılığını gösteren referans tablo.

Mapping Kapsamı

Request modeli, UBL 2.1 CreditNote XML'e doğrulama sağlayıcısı, alıcı/vekil bilgileri, iade referansı, kargo ve belge satırları üzerinden yansır.

Kısa kural: Entegratör iş kararlarını request alanlarıyla gönderir; platform bu alanları UBL XML node'larına ve GİB rapor alanlarına dönüştürür. Kargo şirketi bilgilerinin tamamlanacağı akışlarda entegratör yalnızca kargo şirketi kodunu gönderir.

Entegratör sorumluluğu: Hazır UBL endpointlerinde gönderilmesi gereken alanlar, Add/Update özel durumları ve başarılı/başarısız örnekler Entegratör Sorumlulukları sayfasında yer alır. Bu sayfadaki tablo, request alanlarının UBL path karşılıkları için kanonik referanstır.

Uygulama Notları

Mapping notları, platformun otomatik tamamladığı alanlar ile entegratörün göndermesi gereken alanlar arasındaki sınırı netleştirir.

Vekâletli UBL uyarısı: Vekâleten yapılan iadelerde doğrulama bilgisinin gönderileceği Contact konumu değişir. Asıl alıcı AccountingCustomerParty içinde korunmalı; vekil ve doğrulama bilgileri BuyerCustomerParty altında gönderilmelidir. Tam kural ve XML örneği için Entegratör Sorumlulukları bölümünü inceleyin.
Note[] hakkında: Platform, entegratörün gönderdiği listeye kendi ürettiği bir cbc:Note ekler (tutarın yazıyla karşılığı). Bu nedenle UBL çıktısındaki Note sayısı, request'te gönderilenden bir fazla olabilir.
