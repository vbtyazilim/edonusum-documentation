API

Request → UBL XML Mapping

Entegratörün gönderdiği JSON alanlarının UBL Invoice XML'deki karşılığını gösteren referans tablo.

Mapping Kapsamı

Kısa kural: Entegratör üç farklı gövde formatından birini gönderebilir: JSON (AddOutgoingInvoice), platformun düz XML modeli (AddOutgoingInvoiceByXml) veya UBL-TR Invoice belgesi (AddOutgoingInvoiceByUbl). Bir model alanının UBL standardında tanımlanması ile platformun UBL girişinde o alanı okuması ayrı sözleşmelerdir; aşağıdaki tablo platformun gözlenebilir dönüşümünü gösterir.

InternetPaymentPlatformun UBL girişinden request modeline aktarılmaz.İnternet satışı alanları JSON veya platformun düz XML modeliyle gönderilmelidir.
İnternet satışı alanlarının giriş biçimi: Platformun UBL giriş işlemi InternetPayment alanını request modeline aktarmaz. Bu bilgileri gönderecek entegratörler JSON (AddOutgoingInvoice) veya platformun düz XML modelini (AddOutgoingInvoiceByXml) kullanmalıdır. Düz XML biçimi platform model alanlarını kullanır; UBL cac:/cbc: isim alanlarıyla karıştırılmamalıdır.

Uygulama Notları

ÖKC referansı gönderilirken DocumentTypeCode alanının literal olarak OKCBF, DocumentType alanının literal olarak OKCBilgiFisi değerini taşıması zorunludur; bu ikisi ve Id/IssueDate/DocumentDescription/Attachment.ExternalReference/IssuerParty.EndpointId/ValidityPeriod.StartDate alanlarından herhangi biri eksik veya uyumsuzsa istek "SCHEME" koduyla reddedilir (bkz. Teknik Referans — Katman A). İnternet satışı senaryosunda faturanın Note alanına "Bu satış internet üzerinden yapılmıştır." ibaresinin eklenmesi VUK 509 md. IV.2.4.5 gereğidir; bu ibare için UBL tarafında ayrı bir zorunlu eleman yoktur, serbest metin olarak cbc:Note'a taşınır.
