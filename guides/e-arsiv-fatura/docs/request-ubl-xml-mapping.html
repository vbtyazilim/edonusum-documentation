API

Request → UBL XML Mapping

Entegratörün gönderdiği JSON alanlarının UBL Invoice XML'deki karşılığını gösteren referans tablo.

Mapping Kapsamı

Kısa kural: Entegratör üç farklı gövde formatından birini gönderebilir: JSON (AddOutgoingInvoice), platformun kendi düz XML modeli (AddOutgoingInvoiceByXml — InvoiceRequestModel'in XmlElement/XmlArray adlarıyla birebir serileştirilmiş hali) veya gerçek OASIS UBL-TR Invoice belgesi (AddOutgoingInvoiceByUbl). Bu üçü arasındaki alan karşılığı her alan için aynı değildir — bazı alanlar UBL tarafında hiç karşılığı olmayabilir; bu sayfa bunu koddan doğrulanmış şekilde ayırt eder.

Bu alanları doldurmak isteyen entegratörler AddOutgoingInvoiceByUbl yerine JSON (AddOutgoingInvoice) veya platformun kendi düz XML modelini (AddOutgoingInvoiceByXml) kullanmalıdır — bu iki formatta InternetPayment ve alt alanları, C# model adlarıyla birebir aynı (<InternetPayment><WebAdresi>...</WebAdresi>...</InternetPayment>) şekilde gönderilir; OASIS UBL isim alanı (cac:/cbc:) taşımaz.

Uygulama Notları

ÖKC referansı gönderilirken DocumentTypeCode alanının literal olarak OKCBF, DocumentType alanının literal olarak OKCBilgiFisi değerini taşıması zorunludur; bu ikisi ve Id/IssueDate/DocumentDescription/Attachment.ExternalReference/IssuerParty.EndpointId/ValidityPeriod.StartDate alanlarından herhangi biri eksik veya uyumsuzsa istek "SCHEME" koduyla reddedilir (bkz. Teknik Referans — Katman A). İnternet satışı senaryosunda faturanın Note alanına "Bu satış internet üzerinden yapılmıştır." ibaresinin eklenmesi VUK 509 md. IV.2.4.5 gereğidir; bu ibare için UBL tarafında ayrı bir zorunlu eleman yoktur, serbest metin olarak cbc:Note'a taşınır.
